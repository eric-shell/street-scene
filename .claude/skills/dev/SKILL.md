# Run the app

Screenshots are what make this skill expensive: every image read stays in the conversation and is paid for again on each later turn. Answer from text first (`--eval` on `window.__nr`, console errors, the meter) and take a screenshot only when the question is how something looks.

1. Server: `nc -z 127.0.0.1 5175 && echo up`, and reuse it if so (Vite hot-reloads; changes under `src/sim` or `src/city` need a page reload to rebuild the world). Otherwise start `npm run dev` with `run_in_background: true` and wait for its `Local:   http://localhost:5175/` line. The port is pinned (`strictPort`): if something else holds it, say so rather than changing the port. Stop a server you started when done, unless the user is using it.
2. Look with `node .claude/skills/dev/shot.mjs '<path?params>' [out.png] [options]`, never a Playwright script of your own (about 30 s a run). It opens the page in headless Chromium on software WebGL, waits for `window.__nr`, settles, presses the keys, and prints one JSON line: `errors` (console and page errors), `result` (the `--eval`) and `fps` (the meter's text). Options: `--eval '<expression>'` returning a small JSON value, `--keys 'KeyW:3000,KeyN:500,Escape'` (a hold in ms, or one press), `--wait <ms>` before the keys (default 2500; a race's countdown takes about 3 s), `--size WxH` (default 960x540), `--clip <selector>` (one element). The PNG is written only when `out.png` is given; put it in the scratchpad.
   - One screenshot per question at the default size, read once and never again. Compare before and after with `--clip` on what changed rather than two full pages; go larger only for detail the user asked about.
   - When the user has the game open, asking them what they see is cheaper than a screenshot. Audio only starts after a click or key press (browser autoplay rules); not a bug.
3. URL params:
   - `?race=circuit|sprint|drift` straight into a race (3 laps / point to point / 2 laps); `?freeroam` (open world, no rules); `?garage`; `?drone` (these skip the boot splash; a plain load shows it for about 3 s before the menu)
   - `?seed=<anything>` for a fixed city (default is the UTC date); `?quality=low|medium|high|auto`; `?fps` (meter: fps, frame time, auto level and aim); `?walls` (dev builds: every sim wall drawn at the height a car meets it, coloured by look, the 3 m push-back band behind one sided walls in red, prop collision rings; `render/wallOverlay.ts`)
   - `?dev` garage dev mode (Ctrl+Shift+D, then drag a GLB onto the window to try a part); `?build=<share code>`
   - Debug mode (Settings > Developer, `debugMode` in `nightrun.settings.v1`): physics (` / F2) and camera (F3) tuning panels in races and free roam; free roam applies the car's saved physics tuning
4. `window.__nr` exposes the live objects: `{ world, gr, stage, showreel, autoQ }` on the menu, `{ session, gr, autoQ }` in a race (`session.race` is the `RaceState`, `session.race.cars[0].state` the player car), `{ garageScreen, gr, stage, autoQ }` in the garage. Read state through `--eval` instead of adding debug code.
   - `?perf=<seed>&quality=medium&secs=40&label=base[&vs=base]` (dev builds, `game/perfRun.ts`): autopilot drives a circuit while frame, submit and GPU ms and scene-pass tris/calls are sampled; read `window.__nr.perf` (`node .claude/skills/dev/shot.mjs '/?perf=20261019&quality=medium&secs=6' --until 'window.__nr?.perf?.done' --eval 'window.__nr.perf'`). Headless scene counts: `npm run perf:scene`.
5. Performance happens on the user's device, not here: headless software WebGL reads about 4 fps, so ask the user to open `?fps` and read the meter, like `117 fps · 8.5 ms · Auto (High) 6/8 aim 120`. Targets (CLAUDE.md): aim 120 fps, hold 60, never below 30. A frame time pinned at the display's refresh (8.3 or 16.7 ms) means headroom; above 16.7 ms at Medium is a regression to fix, above 33 ms a bug. `?quality=high&fps` is the stress check, `?quality=auto&fps` the default path; `window.__nr.autoQ.stats` has the controller's median, p90 and slow fraction, and `.aim` the frame time it is aiming at. Compare before and after on the same seed and camera.

Keys (`--keys` takes these as Playwright names: `KeyW`, `Space`, `Escape`, `Backquote`): W/S throttle and brake, A/D steer, Space handbrake, N nitrous, G horn, R reset, C camera, Esc pause, ` tuning panel and F3 camera panel (debug mode only). README.md has the full table.
